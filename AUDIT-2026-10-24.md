## 4. Kebenaran sync antar spreadsheet

| # | Temuan (dampak) | Perbaikan |
|---|---|---|
| **S1** | **Data dobel.** `writeInspection_()` selalu `appendRow`. Bila submit timeout padahal sheet sudah tertulis, antrean lokal mengirim ulang → **baris kedua** untuk inspeksi yang sama. | Server memeriksa kolom `ID Inspeksi`: `clientId` yang sudah ada → **tidak menambah baris**, mengembalikan baris lama (`duplicate: true`). ID kini `FSI-<ms>-<acak>` (sebelumnya hanya `<ms>`, bisa bentrok). |
| **S2** | **Urutan "inspeksi terakhir" salah.** Perbandingan memakai string: `"2026-03-05 9:14:00" > "2026-03-05 10:00:00"`, sehingga unit bisa menampilkan inspeksi jam 09:14 sebagai yang terbaru. | `src/lib/time.js` — satu parser (`tsMs`) untuk semua format; `latestByUnit`, sort riwayat, dan `relativeTime` memakai epoch ms. |
| **S3** | **Format waktu campur** — sheet menyimpan teks lokal, `submit` mengembalikan ISO UTC. Dua baris di cache jadi tidak bisa dibandingkan (`' '` < `'T'`). | Semua waktu keluar sebagai **ISO 8601 +07:00**; `rowToRecord_()` dipakai bersama oleh `submit` dan `history` agar bentuknya identik. |
| **S4** | **Safari/iPhone** menganggap `new Date('2026-03-05 7:00:00')` = *Invalid Date* → waktu tampil "—". | Parser menangani teks lokal (jam tanpa nol depan), tanggal saja, DMY, ISO berzona. |
| **S5** | `readHistory_()` mengandalkan urutan baris sheet; baris yang disisipkan manual merusak urutan. | Diurutkan di server berdasarkan waktu, lalu di klien diurutkan ulang (epoch ms). |
| **S6** | Antrean lokal: setelah terkirim, record lama tetap di cache; pending yang ternyata sudah masuk sheet tetap tampil → **tampak dobel di layar**. | `fetchHistory` mencocokkan `clientId` server ↔ pending, membuang yang sudah masuk; hasil disimpan dengan `id` server. |
| **S7** | `flushQueue` mencoba semua item meski endpoint mati (bisa menggantung lama). | Berhenti setelah 2 kegagalan beruntun. |
| **S8** | Jam inspeksi memakai waktu browser; HP dengan zona lain bisa mencatat tanggal berbeda. | Tanggal inspeksi & "hari ini" dihitung dari kalender **WIB**. |

## 7. Kecepatan sinkronisasi (terukur)

Pengukuran memakai server tiruan Apps Script (Node) yang menjalankan `Code.gs` asli + browser
Chromium mobile 390×844:

| Skenario | Hasil |
|---|---|
| Sinkron pertama, 275 sesi / 10.513 titik komponen | **± 1,0 s**, payload **115 KB** (sebelumnya ± 300 KB) |
| Sinkron ulang tanpa perubahan | **69 byte** (revisi cocok → server hanya mengonfirmasi) |
| Kirim inspeksi baru dari HP | 1 baris bertambah, **baris ke-2 tidak bertambah saat dikirim ulang** |
| Sinkron penuh → render daftar 275 riwayat | < 0,4 s setelah payload diterima |

Teknik yang dipakai:
1. **Revisi (`rev`)** = `jumlah baris : jumlah kolom : waktu modifikasi file`. Bila sama, server
   membalas `{unchanged:true, rev, count}` — 70 byte.
2. **Kompresi kolom komponen**: nilai A/B/C per unit dikirim sebagai satu string
   (`"AAB-A…"`) dengan `kmap` berisi nama komponen sekali saja → **−61 %**.
3. **Payload ramping**: field dan komponen kosong tidak dikirim.

## 7b. Distribusi Skor per jenis aset (permintaan lanjutan)

- Histogram "Distribusi Skor" kini **dua batang per rentang**: Mesin (engine) & Irrigator,
  lengkap dengan jumlah di atas batang dan legenda.
- Klik batang → **pop-up analisis** untuk tipe + rentang tersebut: ringkasan angka,
  analisa naratif, sebaran status & wilayah, komponen bermasalah, serta daftar unit
  (skor terendah dulu) dengan aksi **Inspeksi** / buka detail unit.
- Kode unit di pop-up membuka **detail unit sebagai lapisan di atas pop-up** (tetap di tab Dashboard,
  tidak lagi melempar ke tab Data Unit); Esc hanya menutup lapisan detail.
- Di HP tersedia tombol **Mesin / Irrigator** per rentang (target sentuh 36 px) karena
  batang grafik terlalu kecil untuk jari.
- Daftar unit di pop-up memakai **paging 10 per halaman** (opsi 25/50) dengan penunjuk rentang
  dan tombol Sebelumnya/Berikutnya; kartu item dirapatkan (2 baris) agar 10 item muat tanpa
  gulir panjang, dan area isi otomatis menggulir ke awal daftar saat berpindah halaman.
- Diuji: 20 pemeriksaan Playwright (desktop 1280×900 & HP 390×844) — batang terbaca,
  legenda benar, pop-up terbuka untuk kedua tipe, tidak melebihi layar, Esc menutup,
  navigasi ke Inspeksi/Detail unit bekerja, 0 error JS.

```bash

node tools/pagetest.mjs            # paging daftar unit di pop-up (10/25 per halaman)
node tools/detailtest.mjs          # detail unit dari pop-up (lapisan, Esc, tombol Inspeksi)
node tools/edittest.mjs            # ubah & hapus sesi inspeksi (butuh tools/mockapi.mjs)
node tools/audit2.mjs              # audit layout 5 rute × 4 lebar layar
node tools/clicksweep.mjs          # klik semua tombol di 5 rute (201 elemen)
node tools/datacheck.mjs           # konsistensi angka UI vs data mentah
node tools/e2e.mjs                 # sinkron + kirim inspeksi ke server tiruan
```

> Perkakas uji ada di folder `tools/` (memakai `playwright-core`).
