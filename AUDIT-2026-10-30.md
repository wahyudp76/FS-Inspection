# 9. Tombol “Repair All” di banner peringatan (v1.9.11)

Permintaan: pada banner notifikasi error, sediakan tombol **Repair All** yang
memperbaiki persis apa yang dilaporkan banner dan **langsung mengubah data di
spreadsheet** (tanpa harus masuk ke Pengaturan).

## 9.1 Yang ditambahkan

| Lapisan | Perubahan |
| --- | --- |
| `apps-script/Code.gs` | aksi baru **`repairall`** (satu panggilan menjalankan tiga perbaikan berurutan) + aksi **`svcdedupe`** + fungsi `serviceDedupe_()` |
| `src/lib/api.js` | `repairAll()` — memanggil `repairall`, membuang cache master/riwayat/service, dan menyusun ringkasan hasil. **Fallback otomatis** untuk deployment Apps Script lama: `repair` + `svcrepair` dijalankan bertahap bila aksi `repairall` belum ada |
| `src/App.jsx` | `doRepairAll()` — konfirmasi → perbaiki sheet → tarik ulang master/riwayat/service → toast ringkasan; status `repairing` diteruskan ke halaman |
| `src/pages/Dashboard.jsx` | banner “Data sheet perlu diselaraskan” kini punya tombol **Repair All** (dengan konfirmasi berisi daftar tindakan) + tombol **Rincian** ke Pengaturan |
| `src/pages/Service.jsx` | panel “catatan kualitas data” juga punya **Repair All** (dipakai untuk baris ganda service & rumus) |
| `src/pages/Settings.jsx` | tombol **Perbaiki otomatis** memakai jalur `repairAll()` yang sama, jadi ketiga tempat berperilaku identik |
| `Code.gs` `parseTanggal_` | menerima tahun 2 digit (“17/09/26”) — sebelumnya baris seperti ini terlewat saat dedupe |

## 9.2 Apa yang dikerjakan “Repair All” (semuanya menulis ke spreadsheet)

1. **Ringkasan inspeksi** — mengisi komponen kosong dari master lebih dulu, lalu
   menghitung ulang A/B/C/Total/Skor/Kondisi untuk semua baris “Data Inspeksi”.
2. **Master Mesin & Irrigator** — ringkasan A/B/C/Skor/Kondisi + warna kolom
   KONDISI (status *Rusak* selalu Kritis).
3. **Rumus service** — kolom D–F (Month / Bulan Service / Minggu Service) di
   tb_service2 yang `#ERROR!`/kosong ditulis ulang dengan pemisah `;`.
4. **Baris ganda tb_service2** — duplikat (posisi + kode + tanggal + HM sama)
   dihapus, baris pertama dipertahankan.

Setelah selesai, web otomatis menarik ulang master + riwayat + service, sehingga
angka di layar dan isi sheet kembali sama (dan banner hilang sendiri).

## 10.2 Bug baru yang ditemukan & diperbaiki

1. **Baris sampah di “Data Inspeksi” (kritis).** Memanggil aksi `submit` dengan
   payload kosong menambah satu baris berisi kode `null`, tipe `null`,
   0 komponen, dan Kondisi **Kritis** (terbukti saat uji: `FSI-UJI-DOBEL`).
   Baris seperti ini mengotori hitungan Dashboard, laporan KPI, dan master.
   → `writeInspection_()` di `apps-script/Code.gs` sekarang menolak lebih dulu:
   `Data inspeksi ditolak: “Kode Unit” kosong…`, `…Tipe Unit harus Mesin atau
   Irrigator…`, `…tidak ada komponen yang dinilai…`.
2. **Pesan palsu “Endpoint belum diatur”.** `isConfigured()` hanya menerima URL
   `script.google.com`, sehingga Web App yang dipasang di domain lain (mis.
   proxy/`script.googleusercontent.com`) dianggap belum dikonfigurasi.
   → sekarang menerima pola apa pun yang berakhiran `/exec` dengan skema http(s).
3. **Uji tulis yang dulu “hijau” ternyata membandingkan hal yang salah.** Server
   mengirim komponen sebagai satu string `k` + `kmap`; uji lama membandingkan
   ringkasan A/B/C dengan objek `komponen` yang belum diurai sehingga selalu
   0/0/0. Uji kini mengurai `k` persis seperti `expandRecords()` di web.

## 10.4 Performa — temuan & perbaikan

Probe: `node tools/perfcheck.mjs` (build `docs/`) + `node tools/refreshtest.mjs` (baru).

| Metrik | Hasil |
|---|---|
| Bundel `docs/` | 9 berkas, 1 193 kB (js 1 003 kB · css 56 kB) |
| Rute Dashboard | TTFB 13 ms · DOMContentLoaded 115 ms · load 116 ms · KPI siap 1,4 dtk |

| DOM / grafik | 1 471 elemen · 15 grafik · heap 17 MB (Service 22 MB) |

| Respons Apps Script | history 90 ms/115 kB · master 18 ms/41 kB · svcread 4 ms/40 kB · audit 53 ms |

**Temuan utama:** tarikan otomatis tiap 5 menit **selalu** meminta data penuh
(`force: true`), sehingga web mengunduh ulang ±155 kB (115 kB riwayat + 41 kB
master), mengurai ulang 275 baris, lalu menghitung ulang 15 grafik — padahal
Apps Script sudah mendukung `rev` dan bisa menjawab “tidak berubah”.

**Perbaikan (`src/lib/sync.js`, `src/App.jsx`):**
- `syncAll({ paksa })`: tarikan otomatis mengirim `rev` terakhir, Sinkron manual
  tetap `paksa: true` (selalu data penuh — pengguna menekan Sinkron karena yakin
  ada perubahan).
- State layar tidak lagi ditimpa saat balasan `unchanged` (tidak ada render ulang
  percuma dari data yang sama).

**Hasil terukur (`tools/refreshtest.mjs`):**

```
tarikan otomatis  : master(rev, 129 B) · history(rev, 72 B)   → 201 byte
Sinkron manual    : master(penuh, 41 618 B) · history(penuh, 117 572 B)
```

→ **±159 kB → 201 byte (−99,9%)** untuk setiap tarikan otomatis, dan grafik tidak
dihitung ulang bila sheet tidak berubah. Tombol Sinkron tetap penuh sesuai
kontrak lama.

## 12.2 Temuan: situs GitHub Pages dulu “hidup tapi buta”

Sebelum ronde ini, build `docs/` tidak membawa endpoint, sehingga pengunjung
harus mengisi Pengaturan ▸ Koneksi sheet dulu di **setiap perangkat** — tanpa
itu dashboard hanya menampilkan snapshot statis. Sekarang endpoint produksi
dibawa saat build (`.env.production` → `VITE_APPS_SCRIPT_URL`), jadi:

- pengunjung baru langsung melihat data sheet terbaru tanpa penyetelan apa pun;
- `tools/livedeploy.mjs` membuktikan situs tersambung **tanpa** menyuntik
  localStorage: riwayat 296 kB masuk cache dari endpoint asli, 15 grafik
  tergambar, 0 error JS;
- endpoint per perangkat tetap bisa menimpa lewat Pengaturan (nilai di
  localStorage menang atas nilai build).

Bila ingin mengembalikan perilaku lama: kosongkan baris `VITE_APPS_SCRIPT_URL`
di `.env.production` lalu `npm run build:pages`.

## 12.3 Temuan data dari audit Apps Script (produksi)

`audit` diambil langsung dari produksi: `ringkasan/skor/kondisi/komponenHilang/
komponenAsing/idGanda/kodeAsing/tanggalRusak` semuanya **0**. Satu-satunya angka
yang bergerak: **42 unit “beda status”** (audit 1 November: 19).

Arah selisihnya dianalisis: **40 unit master “Standby” tetapi inspeksi terakhir
“Terpasang”**, 1 Rusak→Terpasang, 1 Terpasang→Rusak. Penyebabnya bukan web:
`TGL INSPEKSI TERAKHIR` di master masih **2026-03-05 untuk 273 dari 274 unit**,
jadi kolom status master diubah langsung di spreadsheet tanpa mencatat inspeksi
baru. Web menampilkan **status master** (sesuai aturan sheet = otoritas), jadi
tampilan web benar; angka 42 hanya penanda bahwa sheet master dan riwayat
inspeksi belum sinkron.

Tindak lanjut untuk pemilik data: perbarui `TGL INSPEKSI TERAKHIR` saat mengubah
status di master, atau catat inspeksi baru lewat form sehingga riwayat ikut
menguatkan status.
